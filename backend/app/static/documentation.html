📘 Aarogya — Bilingual Voice AI Receptionist for a Clinic

A production-style inbound voice agent that books, reschedules, and cancels clinic appointments over the phone in English and Hindi, backed by live availability and real system integrations.

Back to dashboard Open system prompt

Overview

This solution combines a Bolna voice agent, a FastAPI backend, a React operations dashboard, Supabase Postgres, and Cliniko write-back to create a complete clinic receptionist platform.

  • Voice platform: Bolna (inbound agent — SIP trunk · STT · LLM · TTS · barge-in)
  • Datastore / source of truth: Supabase Postgres
  • PMS system-of-record: Cliniko
  • Telephony carrier: Twilio

backend/ FastAPI tool API, Supabase, Cliniko integration, background workers

Free-tier constraints

This project was intentionally built and tested on free/trial tiers, which influences the architecture and operational behavior.

Architecture

The voice pipeline works whether or not the dashboard is deployed. Bolna owns the live call, the backend exposes tool webhooks and business logic, and Cliniko remains the PMS write-back target.

Call flow

Why Bolna

  • Inbound + tool-calling fits the live phone experience perfectly
  • Small strongly-typed tool schema improves reliability
  • Multilingual voice handling is native at the provider layer
  • Low-latency tool responses and masked holding phrases keep the conversation natural

Multilingual approach

The system prompt instructs the agent to mirror the caller's language, code-switch naturally, and never answer live scheduling questions from memory. The knowledge base is limited to static clinic information only.

The backend

  • Supabase Postgres provides real scheduling data with write-time conflict prevention
  • The availability engine calculates live slots from working hours, bookings, and branch buffers
  • The API exposes 12 tools for identification, patient creation, doctor lookup, availability, booking, rescheduling, cancellation, follow-up logs, and session state persistence
  • Cliniko write-back queues confirmed bookings and retries on failure
  • Session state retention supports dropped-call resume and continuation

Cliniko ↔ Supabase sync

  • Supabase → Cliniko: confirmed bookings are written to Cliniko immediately
  • Cliniko → Supabase: changes made directly in Cliniko are reconciled every 60 seconds
  • Branches, practitioners, appointments, and patients are mirrored bidirectionally

Ops dashboard

  • Overview with KPIs and a live availability finder
  • Inbound / outbound call visibility
  • Appointment, patient, follow-up, and session views
  • Clinic setup information for branches, doctors, and sync state

Outbound calls

Clinic-initiated calls are managed with a retry policy and continuation logic, allowing dropped or missed calls to resume naturally from saved session context.

Eval harness

Scripted multi-turn conversations validate booking success, turns-to-completion, redundant-question count, and tool latency across English, Hindi, and Hinglish.

Run it yourself

# Backend
cd backend
pip install -r requirements.txt
cp .env.example .env
python -m db.apply
python -m seed.seed_cliniko --apply
python -m db.seed_supabase
python run.py

# Frontend
cd ../frontend
npm install
npm run dev

Bolna setup

Because the free-tier dashboard editor is unreliable, the agent is configured using a direct API call with tool definitions and webhook headers. The generated tool payload is produced from the backend Bolna tooling scripts.

Deployment

  • Backend should be deployed to a persistent Python host such as Render or Railway
  • Frontend should be deployed to a static host such as Vercel
  • The frontend needs VITE_API_BASE_URL set to the deployed backend URL

Known limitations

  • Free-tier constraints limit concurrency and outbound reach
  • Cliniko trial cannot create practitioners via API
  • No auth on tool webhooks beyond a shared secret
